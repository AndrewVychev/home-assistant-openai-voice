# Голосовой прототип OpenAI Realtime × Home Assistant

Локальная веб-страница использует микрофон и динамики Mac через WebRTC. OpenAI Realtime выбирает разрешённую сущность, а локальный Node.js backend вызывает её сервис через Home Assistant REST API. Названия комнат считываются из реестров Home Assistant через WebSocket API, включая комнату, назначенную всему устройству.

## Что нужно

- macOS и Node.js 20 или новее;
- доступный `http://homeassistant.local`;
- OpenAI API key с подключённым API-биллингом;
- Long-Lived Access Token Home Assistant.

Ключи остаются только в `.env` на Mac и не попадают в браузер.

## 1. Создать токен Home Assistant

1. Открой Home Assistant.
2. Нажми на свой профиль в левом нижнем углу.
3. Найди раздел **Long-Lived Access Tokens**.
4. Создай токен с названием `OpenAI Voice Prototype`.
5. Скопируй его сразу: Home Assistant показывает токен только один раз.

Для прототипа лучше создать отдельного пользователя Home Assistant и открыть голосовому управлению только безопасные сущности.

## 2. Настроить проект

В Terminal:

```bash
cd /Users/avychev/Documents/Codex/2026-08-22/c/outputs/home-assistant-openai-voice
cp .env.example .env
```

Открой `.env` локальным редактором и замени два значения:

```dotenv
OPENAI_API_KEY=твой_openai_api_key
HA_TOKEN=твой_длинный_токен_home_assistant
```

Не отправляй эти значения в чат и не коммить `.env`.

## 3. Запустить

```bash
npm install
npm start
```

Открой [http://127.0.0.1:3000](http://127.0.0.1:3000), разреши браузеру доступ к микрофону и нажми **Начать**.

Либо нажми **Включить «Шо ты голова»**. При первом запуске запиши не менее 8 вариантов фразы и 8 примеров фонового шума, затем нажми **Обучить модель**. TensorFlow.js дообучит модель `speech-commands` на твоём голосе и сохранит её в IndexedDB браузера. После срабатывания прозвучит короткий сигнал и откроется Realtime-сессия. Когда ассистент закончит ответ, сессия автоматически закроется и локальный wake word включится снова; если ответа нет, действует страховочный тайм-аут.

Блок **Стоимость OpenAI API** использует фактический `usage` из событий `response.done`: показывает цену последней команды, сумму за текущую загрузку страницы и разбивку входных, кэшированных и выходных токенов. Для команды с tool call учитываются и выбор функции, и финальный голосовой ответ.

Prompt caching Realtime API работает автоматически. Чтобы повторные сессии получали одинаковый кэшируемый префикс, список сущностей всегда сортируется по `entity_id`, а меняющиеся состояния `on/off` не включаются в инструкции. Актуальное состояние запрашивается инструментом `get_home_state`. В интерфейсе рядом с количеством кэшированных токенов показывается фактический процент cache hit.

Для экономии аудиовыхода команды управления выполняются без предварительного `get_home_state` и без голосового анонса плана. После результата ассистент отвечает одной фразой до пяти слов. Каждый ответ ограничен `180` output-токенами; проверка состояния остаётся доступна только по явному вопросу пользователя.

Перед запуском можно выбрать режим ответа:

- **Текст — дешевле**: вход остаётся голосовым, но OpenAI возвращает текст в чат без платного аудиовыхода;
- **Голос OpenAI**: ассистент отвечает голосом и одновременно показывает транскрипт.

И wake-word запуск, и ручной запуск большой кнопкой работают в режиме одной команды: после окончания голосового ответа Realtime-сессия закрывается автоматически. Если пользователь не говорит, действует 15-секундный страховочный тайм-аут.

Автозавершение происходит только после фактического tool call в Home Assistant. Если команда неоднозначна и ассистент задаёт уточняющий вопрос, соединение остаётся открытым ещё 15 секунд, чтобы пользователь мог ответить.

Примеры:

- «Включи свет в гостиной»
- «Поставь температуру двадцать два градуса»
- «Какой свет сейчас включён?»

## Проверка конфигурации

Открой [http://127.0.0.1:3000/api/health](http://127.0.0.1:3000/api/health). Endpoint не возвращает секреты — только состояние подключения.

## Безопасность

- Сервер по умолчанию слушает только `127.0.0.1`.
- Доступны только прямые allowlisted-действия для `light`, `switch` и `climate`.
- Shelly-выходы преобразованы встроенными helpers `Switch as X → Light`; скрытые исходные `switch.shelly*` не передаются голосовой модели.
- Перед созданием голосовой сессии модель получает актуальные комнаты (Areas) разрешённых сущностей.
- Conversation API отключён; свободный текст в Home Assistant не передаётся.
- Замки, двери, ворота, сирены и сигнализация не входят в разрешённые домены.

## Docker

После настройки `.env`:

```bash
docker compose up --build
```

При переносе на отдельную машину поменяй `HA_URL`, если `homeassistant.local` там не разрешается.
